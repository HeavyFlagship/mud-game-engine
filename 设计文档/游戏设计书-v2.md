## 文档说明

### 编号规则

- 顶层：`1 世界观设定`、`2 UI与游戏模式`……（系统 / 设定）
- 二级：`1.1 …`（机制 / 设计）——**目录收录到本级**
- 三级：`1.1.1 …`（细则）——仅正文使用
- 四级：`1.1.1.1 …`——仅在确有必要时使用

### 标注体系

设计书只记录设计成熟度，不记录实装状态（不再使用"暂不实现"等表述）。

| 标记 | 含义 | 使用位置 |
| ---- | ---- | -------- |
| 【占位】 | 仅有结构，内容待补（含整章占位的系统） | 目录 + 正文 |
| 【待定】 | 已有内容，但关键方案 / 数值未决 | 目录 + 正文 |
| 【需要处理】 | 存在矛盾、过时或跨系统冲突，需要决策或修订 | 目录 + 正文 |

- **目录标注**：直接缀在条目末尾，如 `10 建筑与据点系统【占位】`。
- **正文标注**：以引用块置于对应段落前，如 `> 【需要处理】……`；细则标题可用行内缀注，如 `#### 5.8.3 电子战【待定】`。
- 标记随整理进展更新；处理完成后移除或降级为普通说明。

### 整理原则

1. **按玩法领域归并系统**：装备、敌人归入战斗系统；物品、采矿、制造、物流归入资源与工业系统；时间轴机制归入世界与场景系统，与战斗解耦。
2. **清理实现层包袱**：代码结构、文件路径、API、MUD 指令集、Demo / MVP 范围等不进入 v2；界面与交互内容只保留设计意图。
3. **修正与标记**：过时表述统一修正；矛盾内容先归并为一致口径，并加【需要处理】标记留待决策。
