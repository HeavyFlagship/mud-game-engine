# 0.1 设计想法

## 文档说明

本文件用于记录讨论过程中产生但**尚未落实到具体设计书**中的想法与灵感，避免跨任务对话时丢失。任何新任务接手前，应先通读本文件，判断其中内容是否与当前任务相关，并将其纳入当前设计。

**记录规则**：

- 每条想法独立成块，至少三行，格式如下（markdown 段内换行需在行尾加两个空格）：
  ```
  [日期-时间] [状态]：  
  **{关键字}**  
  {想法内容}  
  ```
- **日期-时间**：想法提出或记录的时间，采用 `YYYY-MM-DD HH:MM`。
- **状态**：三选一——
  - `未完成`：想法已提出，尚未落实到任何设计书，可被后续任务吸收、细化或推翻。
  - `完成`：想法已落实到对应设计书，内容可被引用验证。
  - `废弃`：想法经讨论后被否决或不再需要，保留记录仅供追溯。
- **关键字**：用简短词条概括想法主题，便于快速检索与识别。
- **想法内容**：用一段话阐述核心设想，必要时补充背景、关联系统或待定项。
- 状态变更时，在原文后追加一行 `→ 完成` / `→ 废弃`（保留原状态记录，便于追溯），仅在行内更新状态字段亦可，但需保留变更痕迹。
- 新增想法一律**追加到文件末尾**，不修改既有条目，保持时间顺序。
- 记录块内每一行末尾均需保留两个空格，以保证 markdown 渲染时正确换行。
