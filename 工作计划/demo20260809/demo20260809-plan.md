## 1. 概述

### 1.1 Demo目标

制作一个**核心循环完整可玩**的Demo版本，玩家可以：

1. 从基地出发，探索10x10的网格地图
2. 遭遇虫族和机械敌人，进入时间轴回合制战斗
3. 击败敌人获得战利品和信用点
4. 返回基地购买装备/载具、补充弹药
5. **在基地工业区安装生产设施，推进开发树解锁**
6. **在交易中心参与供需交易，利用配额制获取补给**
7. 挑战Boss房间，完成探索目标

## 3. 实施计划

### 阶段零：架构重构（第1-2天）

> **核心理念**：Demo不必完全参考原本代码的实现，可以重构。本阶段解决当前代码最核心的架构问题——场景指令分类的switch-case模式不利于扩展，以及各系统耦合度过高。

#### 3.0.1 场景指令架构重构（重点）

**问题分析**：

当前 `command-system.js` 使用两层 switch-case 分发指令（[command-system.js](file:///workspace/mud-game-engine/assets/js/systems/command-system.js#L59-L117) 的 `execute()` 和 `handleBattleCmd()`），存在以下问题：

1. **不可扩展**：每新增一个指令（如 `trade`、`工业`、`安装`、`调度`）都需修改 switch-case 分支
2. **场景不感知**：基地服务层指令（shop/trade/工业/使用设施/安装/调度/replenish/仓库/机库/任务/备份）与战斗/探索层指令（move/fire/call/look/retreat/timeline/wait）混在一起，无法根据当前场景（安全区/战场）动态启用/禁用
3. **紧耦合**：指令处理函数直接调用 Game/Battle/Player 方法，无法独立测试或替换

**解决方案：指令注册表 + 场景上下文**

```
指令注册表（CommandRegistry）
├── 全局指令（任何场景可用）：help, save, load, status, bag, equip, unequip, look
├── 战斗/探索层指令（仅战场场景）：move, fire, call, retreat, timeline, wait, idle, enter
└── 基地服务层指令（仅安全区场景）：shop, trade, 工业, 使用设施, 安装, 调度, replenish, 仓库, 机库, 任务, 备份
```

**数据结构设计**：

```javascript
// 指令注册表
const CommandRegistry = {
  // 全局指令：任何场景下均可执行
  global: {
    help: { handler: 'cmdHelp', desc: '查看帮助' },
    save: { handler: 'cmdSave', desc: '保存游戏' },
    load: { handler: 'cmdLoad', desc: '读取存档' },
    status: { handler: 'cmdStatus', desc: '查看状态' },
    bag: { handler: 'cmdBag', desc: '查看背包' },
    equip: { handler: 'cmdEquip', desc: '装备物品' },
    unequip: { handler: 'cmdUnequip', desc: '卸下装备' },
    look: { handler: 'cmdLook', desc: '查看当前场景' },
    // ...
  },

  // 战斗/探索层指令：仅在战场场景(非安全区)可用
  battle: {
    move: { handler: 'cmdMove', desc: '移动' },
    fire: { handler: 'cmdFire', desc: '攻击目标' },
    call: { handler: 'cmdCall', desc: '与NPC通信' },
    retreat: { handler: 'cmdRetreat', desc: '撤退' },
    timeline: { handler: 'cmdTimeline', desc: '查看时间轴' },
    wait: { handler: 'cmdWait', desc: '等待' },
    idle: { handler: 'cmdIdle', desc: '待机' },
    enter: { handler: 'cmdEnter', desc: '切换场景' },
  },

  // 基地服务层指令：仅在安全区场景可用
  // 对应 世界场景设计书 §4.7 基地服务层
  base: {
    shop: { handler: 'cmdShop', desc: '商店（装备库）' },
    trade: { handler: 'cmdTrade', desc: '交易中心（供需/市场订单）' },
    工业: { handler: 'cmdIndustry', desc: '查看工业区/设施' },
    使用设施: { handler: 'cmdUseFacility', desc: '使用/申请设施' },
    安装: { handler: 'cmdInstall', desc: '安装工业设施' },
    调度: { handler: 'cmdSchedule', desc: '调度设施运行模式' },
    replenish: { handler: 'cmdReplenish', desc: '基础配额补给' },
    仓库: { handler: 'cmdWarehouse', desc: '仓库管理' },
    机库: { handler: 'cmdHangar', desc: '机库/载具管理' },
    任务: { handler: 'cmdQuest', desc: '任务接取/交付' },
    备份: { handler: 'cmdBackup', desc: '意识备份/恢复' },
  }
};
```

**指令分发流程**：

```
用户输入 → CommandSystem.parse()
  → 查找别名
  → 确定指令所属层（global/battle/base）
  → 根据当前场景上下文判断指令是否可用：
      - 安全区场景：global + base 指令可用
      - 战场场景：global + battle 指令可用
  → 调用对应 handler（通过方法名映射到具体实现）
  → 返回结果
```

**具体实现**：

- [ ] **ARCH-1**: 创建 `systems/command-registry.js`，定义三层指令注册表
- [ ] **ARCH-2**: 重构 `command-system.js`，将 `execute()` 改为基于注册表的动态分发
  - 移除 `execute()` 中的 switch-case
  - 移除 `handleBattleCmd()` 中的 switch-case
  - 新增 `getAvailableCommands(sceneType)` 方法，返回当前场景可用的指令集合
  - 新增 `getCommandHelp(sceneType)` 方法，按场景类型返回帮助文本
- [ ] **ARCH-3**: 各指令处理函数从 `CommandSystem` 中解耦，移至独立模块
  - 战斗/探索层指令 → `systems/commands/battle-commands.js`
  - 基地服务层指令 → `systems/commands/base-commands.js`
  - 全局指令 → `systems/commands/global-commands.js`
- [ ] **ARCH-4**: 在 `map.js` 房间数据中增加 `sceneType` 字段（`'safe'` / `'battle'`），用于指令可用性判断
- [ ] **ARCH-5**: `help` 指令按场景类型动态显示可用指令列表

## 7. 假设与决策

| 决策 | 理由 |
|------|------|
| 场景指令采用注册表模式替代switch-case | 设计书要求场景指令分类，switch-case不利于扩展，注册表模式支持按场景类型动态注入指令 |
| 制造系统实现最小闭环（铁矿石→铁锭→钢锭→装甲板） | 验证完整链路的同时控制复杂度，后续可平滑扩展 |
| 经济系统仅实现单基地 | 多基地需要物流系统支撑，超出Demo范围 |
| 仅实现玩家直接生产路径，不实现NPC自动运行 | NPC自动运行需要时间确认+概率判定，增加复杂度且Demo体验不明显 |
| 开发树节点初始解锁铁矿石（代表初始工业基础） | 解决"第一座设施如何建起来"的循环问题，符合设计书 §2.6 |
| 设施安装为小型即时完成 | 避免Demo中等待时间过长影响体验 |
| 保持现有战斗系统不变 | 战斗系统已较完善，Demo重点在制造/经济/指令架构 |
| 弹药制造保留在维修站（作为制造系统入门引导） | 与设施制造形成互补，维修站提供快速消耗品制造，设施提供自动化工业品生产 |

## 8. 风险评估

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| 指令架构重构范围大，影响现有功能 | 现有指令全部失效 | 分步重构：先建注册表框架，再逐个迁移指令，保留旧代码作为回退 |
| 制造系统与经济系统联动复杂 | 供需数据不一致 | 明确接口契约，制造系统产出→经济系统入库为单向数据流 |
| 100个房间+制造+经济数据量大 | 加载变慢 | 房间数据按需生成，制造/经济数据按游戏时间增量更新 |
| Boss战斗平衡难调 | 太简单或太难 | 提供多种难度装备选择，玩家可自行调整 |
| 场景指令分类可能遗漏部分指令 | 用户体验下降 | 通过help指令动态展示当前场景可用指令，降低遗漏影响 |
