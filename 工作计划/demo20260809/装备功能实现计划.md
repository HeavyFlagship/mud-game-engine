# 装备功能实现计划（8 项属性功能确认与实现）

## 一、Summary（任务总览）

用户指出 `equipment-db.js` 与各系统中有 8 类属性对应的功能「疑似未实现」，要求先确认再结合设计书实现。经核对，**当前代码中这些功能确实均未实现**，仅停留在「数据字段 + 元数据标签」层面。本计划按 8 项逐条落地，涉及数据文件、装备系统、战斗系统、地图 UI 四层改动。

### 现状核实结论（探索依据）
- `cargoVolume`：仅作元数据展示，`Player.addItem()`（[player.js](file:///workspace/mud-game-engine/assets/js/systems/player.js#L967-L974)）无体积校验；载具 `cargo`（[vehicles.js](file:///workspace/mud-game-engine/assets/js/data/vehicles.js)）为 200~350（kg 量级），与 m³ 不统一 → **未实现**。
- `generateAmount / materialBay / materialCost`：仅存在于 `ion_generator` 数据中，无任何消耗/产出逻辑 → **未实现**。
- `repairAmount / repairTarget / repairMaterial / repairMaterialCost / energyPerCycle / inCombat`：仅存在于修复器数据，无修复逻辑；修复材料「通用装甲熔铸剂/结构纳米修复剂」在 `MaterialDB` 中不存在 → **未实现**。
- `trackDuration / jamRange / jamStrength / effectRange / effectDuration`：仅数据字段；无 EW buff 系统；电磁干扰区以直接改 `visionRadius` 实现（[battle.js](file:///workspace/mud-game-engine/assets/js/systems/battle.js#L304-L374)），非 buff → **未实现**。
- `visionBonus / scanRange / scanAccuracy / jamResist`：`getEWBonus()`（[player.js](file:///workspace/mud-game-engine/assets/js/systems/player.js#L875-L886)）已聚合但未被调用；雷达图（[battle-ui.js](file:///workspace/mud-game-engine/assets/js/systems/battle-ui.js#L181-L422)）无扫描范围/扫描精度渲染 → **未实现**。
- 废弃属性 `potential / startupReq / baseAccuracy / armorPen / chargeCoeff`：仅在数据与 `_itemAttrMeta` 中，逻辑零引用 → 可安全移除。
- 替换属性 `bayReq`：仅在装备数据与预算计算（[player.js](file:///workspace/mud-game-engine/assets/js/systems/player.js#L727-L756)）中使用，需统一为 `equipVolume`。
- `minRange`：武器数据已有该字段，但 [calculateHitRate](file:///workspace/mud-game-engine/assets/js/systems/battle.js#L638-L659) 只判 `dist > range`，未判最小射程 → **未实现**。

## 二、Current State Analysis（现状）

- 装备数据集中在 `equipment-db.js`；每个装备同时带 `equipVolume`（装备舱体积, m³）与 `bayReq`（重复的旧名字）与 `cargoVolume`（货运体积, m³）。
- 玩家背包 `inventory` 无体积概念；`addItem/removeItem` 无任何限制。
- 预算：`checkBudget/calcUsedBudget` 用 `bayReq`，`budget.bayMax = vehicle.equipmentBay`，而 `equipmentBay` 当前为 200~500（量级错误）。
- 战斗时间轴 `registerUpdaters()` 已注册 `statusEffects/energy/ai/hazards` 等，是挂接生成器/修复器/EW 逻辑的天然入口。
- 状态效果 `statusEffects` 数组与 battle-ui 的 `iconMap` 已存在（burn/slow/corrosion 等），可直接扩展 EW/电磁干扰 buff 类型与图标。
- 商店：`shop all` 会列出 `EquipmentDB.getAll()`，任何装备本就可通过 `shop all 购买`；`quartermaster.shopItems` 决定常规列表。
- 设计书 [装备系统设计书.md](file:///workspace/设计文档/装备系统设计书.md) 提供了各属性的权威语义与数值参考（货运体积 m³／装备舱 m³／发生量/周期／修复量/周期等）。

### 关键设计决定（已与用户确认 / 推断）
- **货舱尺度**：用户选定「机体货舱改为 0.1m³ 量级，物品体积与现有装备数据一致；需大量载货的采矿等活动依靠其它载具实现」。
- **装备不占小货舱**：装备属于「已安装硬件」，安装后走 `equipVolume`（装备舱），不占用 0.1m³ 货舱；货舱体积校验只约束**背包内的普通货物**（材料/消耗品/弹药物品）。否则 0.1m³ 货舱连单件装备都装不下，会导致「买装备→装备」流程在背包即被卡死。此项为保证可玩性的必要推断，实施时在 `addItem` 中按 `目录 id 是否属于 EquipmentDB` 判定豁免。

### 任务 4：电子战装备 + buff 系统 + 电磁干扰区改为 buff

**泛型 buff 工具（`assets/js/systems/battle.js`）**
- 新增 `applyStatusEffect(target, type, duration, extra)`：存在同类型则刷新 duration + 合并 extra，否则 push。供 EW/jam/track/em 复用（`dealDamage` 现有的 burn 等不受影响）。
- `updateStatusEffects` 已能按 duration 衰减并清除，直接支持新 buff。

**buff 类型与效果**
- `em_interference`（玩家 debuff，来自电磁干扰区）：期间扫描/命中受罚（见任务 5/8），浮层由 `updateHazards` 驱动。
- `jam`（对敌人 debuff，来自雷达干扰器）：`calculateEnemyHitRate` 中命中率 × `1/(jamStrength)`（或按 `(1/(1+jamStrength-1))`），强度随干扰器；雷达图上目标坐标以随机扰动呈现「信号干扰」。
- `track`（玩家 buff，来自火控雷达）：改善对锁定目标的命中。
- `blinded`（敌人 debuff，来自闪光器）：降敌命中/视野。

**`registerUpdaters()`** 新增 `Timeline.addUpdater('ew', d => this.updateEW(delta))`：
- 遍历 `Player.getEquippedEW()`：
  - 雷达干扰器（`jamRange/jamStrength`）：对 `jamRange` 内敌人 `applyStatusEffect(enemy,'jam',0.5周期,{strength})`。
  - 火控雷达（`trackDuration/scanRange`）：若 `Battle.getLockedEnemy()` 在 `scanRange` 内，`Player` 施加 `track`（持续 `trackDuration`，且开火时命中 + 加成）。
  - 闪光器（`effectRange/effectDuration`）：`effectRange` 内敌人施加 `blinded`（持续 `effectDuration`）。
  - 更新结束后移除过期/超范围 buff（`updateStatusEffects` 负责超时清）。

**电磁干扰区 → buff（`updateHazards`，[L304-L374](file:///workspace/mud-game-engine/assets/js/systems/battle.js#L304-L374)）**

- EMI 对视野的影响改为在「有效视野计算」处按 buff 折减（见任务 5 的 `getEffectiveVision`），从而变成可被 buff 系统显示/清除的状态而非硬编码。

## 四、Assumptions & Decisions（假设与决策记录）

1. **装备豁免货舱体积**：`EquipmentDB` 装备因装配到装备舱（`equipVolume`）不占用 0.1m³ 货舱；货舱体积只约束材料/消耗品/弹药物品。此为在 0.1m³ 设定下保证「购买→装备」流程可用的必要决定。
2. **材料单位换算**：`generateAmount/materialCost` 单位按设计书为「克/周期」，`resources.ion` 上限单位亦为克，故直接相加，无需额外换算。
3. **修复/产出仅在战斗场景时间轴运行**：挂到 `Timeline.addUpdater`，符合现状（玩家停留在场景/战斗时时间轴持续运行）。
4. **EW 强度为简化数值**：`jam` 对敌命中衰减按 `÷jamStrength`、`track` 对玩家命中 ×1.15、`em_interference` ×0.85，均为便于验证的初始值，可后续调整。
5. **废弃属性彻底删除**（数据+元数据），保留既有装备数值不变（仅删字段）。
6. **`equipmentBay` 取 m³ 合理值**（scout 4 / assault 5 / striker 6 / stealth 3），使 `equipVolume` 成为有意义但非卡的预算；`cargo` 按 0.1m³ 量级。
7. **「机体用超微型离子生成器」「机体用微型装甲修复器」为新条目**，不复用/覆盖既有 `ion_generator` / `armor_repairer`，保持向后兼容。
