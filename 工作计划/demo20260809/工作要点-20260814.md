## 3. 当前进度：战斗操作阶段 UI 化重构（已完成并验证）

### 3.1 需求背景
原操作流程：移动/开火通过命令行 `Msg.prompt` 输出"武器已就绪"等冗余提示，命令行界面臃肿。重构为"装备 UI + 操作序列 + 执行指令"模型。

### 3.2 核心设计
- **操作阶段（Action Phase）**：`Battle.isPlayerActionPhase()` = `active && Timeline.paused && currentActor==='player' && hasLiveEnemies()`
- **操作序列**：`Battle.playerActionState = { active, chassis:{action,target,targetLabel,holdFor,autoExit}, weapons:{slot:{action,target,holdFor,ready}} }`
  - 机体项：可"移动（靠近锁定目标/坐标）"或"待命"
  - 每个就绪武器项：可"开火（锁定目标）"或"待命"；冷却中仅显示状态不可操作
- **执行**：`Battle.executeActions()` 统一提交（机体移动 → `setPlayerTask`；武器开火 → 调度 `player_fire` 事件并行；全部待命 → 等价 continue）
- **锁定目标**：`Battle.lockedTarget`，敌人卡片高亮 + 🔒，`fire`/`move` 无参默认用锁定目标
- **提示栏**：`Msg.hint()` 输出到输入框上方 `#hint-bar`，不进入 `#output` 命令行记录，可关闭（`Msg.hintClose()`）
- **待命X秒**：`holdFor` 字段，执行后经 `baseTime + maxHoldFor - Timeline.time` 计算延迟重询 `player_turn`
- **UI 与指令严格对应**：装备卡片按钮 ↔ `execute/lock/fire/hold/move` 指令

## 4. 最近修复（2026-08-14，commit ba6e81a）
1. **`move north` 全称方向解析**：`cmdBattleMove`/`cmdBattleMovePredict` 此前只认 `n/s/e/w/ne/nw/se/sw`，导致 `move north` 报"未找到目标 north"（这是上次会话卡住的真正原因）。现支持 `north/south/east/west/northeast/northwest/southeast/southwest` 全称，主方向无距离时移动到边界并自动切换场景。
2. **操作阶段 autoExit 丢失**：`setChassisAction` 新增 `autoExit` 参数，`executeActions` 提交移动时使用 `state.chassis.autoExit`，修复"移动到边界不切场景"。
