## 摘要

本次任务围绕四项内容细化"世界场景设计书"：

1. **基地环境/设施表达**：把经济、制造系统中产生的"工业区""交易区"等概念，在场景中以"类似掩体（covers）的展示形式"落地，主要参数为**面积**。
2. **场景指令与基地服务**：把当前程序"整场景可用指令来区分战斗区/安全区/商业区"的模式，正式确立为"基地＝场景指令清单"的统一设计，并明确指令清单。
3. **纳入 0.1-设计想法**：其中"玩家据点与基地同接口"与本任务高度相关，纳入并更新状态。
4. **Demo 前缺漏体检**：检查设计书在准备 demo 版本前还缺什么，列出缺漏与建议。

用户要求：计划尽量详细，**不生成文件，用文字反馈**。因此本文件为规划文档，实际修改仍落在"世界场景设计书"上（执行阶段进行）。

## 一、现状分析（基于代码与文档勘察）

### 1.1 基地场景当前的展示方式（程序侧）
- [map.js](file:///workspace/mud-game-engine/assets/js/data/map.js) 中，基地（`outpost_*`）每个房间只有：
  - `desc`（文字描述）、`isSafeZone: true`、`isShop`、`npcs`、`exits`、极少量 `covers`。
- [game.js `look()`](file:///workspace/mud-game-engine/assets/js/systems/game.js#L69-L119) 只输出房间名、desc、出入口、NPC、地上物品、商店提示。
- **[缺口]**：基地场景完全没有"工业区、交易区、维修坊、仓库"等**功能设施**的环境/设施表达；`covers` 里只有极少量掩体，且无面积参数。

### 1.2 经济/制造系统已定义、但未落到场景的概念
- **工业区**：[制造生产系统设计书 §3.3.3](file:///workspace/设计文档/制造生产系统设计书.md) 定义"工业区"为承载设施的实体，核心属性是**工业区面积**；设施有**占地面积**，安装后占用面积。
- **交易中心**：[经济系统设计书 §2.2.1 / §4](file:///workspace/设计文档/经济系统设计书.md) 定义"多基地多交易中心"，交易中心是玩家交互界面（中央大厅/军需窗口/矿区临时点等）。
- **[缺口]**：这两个概念只在系统文档中用"面积/数据"抽象描述，**没有定义它们在基地场景中长什么样、如何可视化**。

### 1.3 场景指令的现状
- 程序已存在"整场景可用指令"模式：战斗区用 `move/fire/call/look/retreat/timeline/wait`（[command-system.js](file:///workspace/mud-game-engine/assets/js/systems/command-system.js#L29-L31)）；基地安全区另有 `shop/trade/replenish/仓库/机库/装备/背包` 等服务指令。
- **[缺口]**：设计书未把"场景指令＝基地服务"这一模式**统一、确定**下来，也没有一份完整的"基地服务指令清单"。

### 1.4 0.1-设计想法中的相关条目
通读 [0.1-设计想法.md](file:///workspace/设计文档/0.1-设计想法.md) 后，与本次任务相关的为：
- **玩家据点与基地同接口**（[未完成](file:///workspace/设计文档/0.1-设计想法.md#L36-L39)）：基地＝场景追加指令清单，玩家据点＝地图新增指令清单。→ 直接支撑本任务第 2 点。
- 其余条目（基地配额独立计数、物流归属NPC、组织系统、设施审批、运转资金、开发树初始解锁、设施规模弹性）与"世界场景"关系较低，本次**暂不纳入**（见第三章说明）。

## 二、本次对"世界场景设计书"的修改方案

### 修改点 A：新增"基地功能设施（工业区/交易区）的环境与设施表达"

**位置建议**：在 §4.3（场景展示方案）之后、§4.4（场景风貌元素库）附近，新增一节 **§4.6 基地功能设施（人类据点内的功能区）**；并在 §4.4.3（建筑结构）中补充"功能区"类型的说明。

**核心设计**：
1. **概念对齐**：基地场景中的功能区（工业区、交易区、维修坊、仓库、指挥室、机库等）是**经济/制造系统数据的场景化呈现**。它们既像 `covers` 一样在场景中占据一块区域、可被看到，又承担系统功能（工业区承载产能、交易区承载订单）。
2. **展示形式＝类似掩体**：每个功能区在 `battlefield` 中表达为一个区域型地物，字段与 `covers` 兼容（`pos/size/height/durability`），**额外增加面积类参数**。
   ```
   功能区（facilityZones）字段建议：
   {
     zone: 'industrial' | 'trade' | 'maintenance' | 'storage' | 'command' | 'hangar',
     name: '工业区',
     area: 1200,        // 总面积 m²（经济/制造系统读取）
     areaUsed: 450,     // 已占用面积 m²
     capacity: 8,       // 可容纳设施数（可选）
     facilities: [ { facilityId, name, footprint: 300, state } ],  // 已装设施
     pos: [x, y], size: [w, h], height: h, durability: d,  // 场景展示（兼容 covers）
   }
   ```
3. **与系统接口**：
   - **工业区**：`area / areaUsed` 与 [制造 §3.3.3](file:///workspace/设计文档/制造生产系统设计书.md) 的"工业区面积/设施占地面积"对接；`工业/使用设施/安装/调度` 指令在此功能区上生效。
   - **交易区（交易中心）**：`trade` 指令在此功能区上生效，对应 [经济 §4](file:///workspace/设计文档/经济系统设计书.md) 的交易中心。
4. **场景呈现**：进入基地场景时，`look()` 输出各功能区的风貌描述（如"东南侧是灯火通明的工业区，几座高炉正喷吐着橘红火光"），并列出可用服务指令（见修改点 B）。
5. **地貌衔接**：基地功能区沿用 `metal_floor` 地形，无地形惩罚；工业/交易区可附带少量环境危害（如工业区高温、交易区人流噪声不影响战斗）。

### 修改点 B：正式确立"场景指令＝基地服务"模式

**位置建议**：新增一节 **§4.7 场景指令与基地服务**（或并入 §4.3 展示方案），并在文档中明确"基地＝安全区＋场景指令清单"。

**核心设计**：
1. **模式定性**：人类据点/基地 **不制作可自由探索的城市**，而是作为"安全区场景"，通过**场景指令清单**暴露所有功能。每一条指令对应一项服务。这与开放世界游戏中"城市功能通过菜单访问"的呈现一致（用户原话）。
2. **场景指令两层分类**：
   - **战斗/探索层**（普通场景）：`move / fire / call / look / retreat / timeline / wait / idle` 等（沿用现有实现）。
   - **基地服务层**（安全区场景）：为一组**服务指令清单**。
3. **基地服务指令清单（建议）**：
   | 指令 | 服务 | 关联系统 |
   |------|------|----------|
   | `shop` | 商店（装备库） | 装备 |
   | `trade` | 交易中心（供需/市场订单） | 经济 |
   | `工业` | 查看工业区/设施 | 制造 |
   | `使用设施` | 使用/申请设施 | 制造 |
   | `安装` | 安装工业设施 | 制造 |
   | `调度` | 调度设施运行模式 | 制造 |
   | `replenish` | 基础配额补给 | 经济 |
   | `仓库` / `机库` | 仓库/机库管理 | 装备 |
   | `任务` | 任务接取/交付 | 任务（待定） |
   | `备份` | 意识备份/恢复 | 世界观 |
4. **"指令清单＝场景能力"的统一接口**：明确"基地＝场景追加指令清单"，并顺带落实设计想法"玩家据点＝地图新增指令清单"（同一接口，复用面积/指令逻辑）。本条写入文档并在 0.1 中标记完成。
5. **进入/离开**：进入安全区场景即列出可用服务指令；`look` 重列；指令在安全区内随时可用，不进入战斗模式。

### 修改点 C：更新文档目录与小结
- 更新 [世界场景设计书.md](file:///workspace/设计文档/世界场景设计书.md) 顶部目录，加入新增的 §4.6、§4.7。
- 在 §6 小结中补充"基地功能设施的环境表达"与"场景指令＝基地服务"两条定位。

## 四、Demo 前设计缺漏体检（修改点 D）

目标：在开始制作 demo 版前，识别设计书层面还缺什么。以下为**当前各文档与程序之间的缺口**，按"必须/建议/可延后"分级：

### 4.1 检查范围
- 遍历全部 10 个设计文档 + 程序实现，对照"能否支撑一个可运行 demo"来判断。

### 4.2 关键缺漏清单

| # | 缺漏 | 影响 | 建议级别 | 处理建议 |
|---|------|------|----------|----------|
| 1 | **场景指令与基地服务规范未确定** | demo 的基地交互无统一入口 | 必须 | 本次修改点 B 解决 |
| 2 | **工业区/交易区的场景表达缺失** | 经济/制造功能无法在场景呈现 | 必须 | 本次修改点 A 解决 |
| 3 | **NPC 系统设计书缺失** | 物流、可交易NPC、采集交付均依赖它，demo 跑通交易/物流受阻 | 必须（demo 需最小版） | 补一份最小 NPC 系统设计书，或先以静态 NPC 简化 |
| 4 | **建筑系统设计书缺失** | 玩家据点建造无定义 | 建议（demo 可先不做玩家据点） | 若 demo 含玩家据点则补最小版，否则延后 |
| 5 | **经济/制造最小数值未定** | 供应链最小闭环（铁矿石→铁锭→钢锭→装甲板）只有概念，无数值 | 必须 | demo 需一整套最小数值（产出/消耗/价格/进度） |
| 6 | **世界场景(100×100网格)与现有小地图差距** | 设计书是开放网格，程序只有前哨+荒原+矿洞 | 必须（需决策） | demo 建议做**垂直切片**（沿用现有小地图 + 新增工业/交易区），而非完整 100×100 网格 |
| 7 | **世界时间粒度未明确** | 设计书说跨场景行军推进世界时间/季节，程序时间轴是战斗秒级 | 建议 | demo 需明确世界时间（天/小时）与战斗时间（秒）的换算 |
| 8 | **任务/主线系统缺失** | 世界场景设计书大量任务关联，但无任务系统设计书 | 建议 | demo 可把"任务"作为场景指令的最小形式承载 |
| 9 | **多基地架构落地口径** | 经济定义多基地多交易中心，世界场景只有主城赤穹中枢 | 建议 | demo 先单基地（主城），多基地留待中期 |
| 10 | **基地功能区数据字段** | 需在 map.js room/battlefield 增加 `facilityZones` | 必须 | 执行阶段在代码侧补充字段与 `look()` 展示 |

### 4.3 对 demo 范围的建议（供决策，非本任务执行项）
- **推荐 demo 形态**：在现有小地图（前哨基地 + 荒原 + 矿洞）上，为基地加入"工业区/交易区"功能区与场景指令清单，打通"采集→交付→交易→制造→补给"的最小闭环，作为可测试的垂直切片。
- 完整 100×100 网格开放世界、多基地、玩家据点、NPC 物流网络，建议作为 demo 之后的下一阶段。

### 4.4 需要用户确认的决策点
1. demo 是否包含**玩家据点建造**（决定建筑系统是否需最小版）。
2. demo 时间粒度：是否引入**世界时间（天/小时）**，还是继续纯战斗秒级时间轴。
3. demo 是否实现**多基地**，还是单基地主城。
